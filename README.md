# README: Две реализации консольного фреймворка для управления заданиями

## Общее описание
В данном репозитории представлены две альтернативные реализации консольного приложения для управления и выполнения пользовательских заданий. Обе программы решают одну задачу, но используют разные архитектурные подходы.

---

## Ветка 1: Рефлексивный подход (library)

### Описание
Реализация, основанная на использовании рефлексии для динамического обнаружения и выполнения методов-заданий. Все задания находятся в одном классе как методы.

### Архитектура

#### Иерархия классов
```
Core (базовый класс)
  └── StopStart (промежуточный класс)
        └── Methods (класс с заданиями)
```

#### Ключевые компоненты
- **Core**: Реализует основную логику работы с рефлексией и меню
- **StopStart**: Предоставляет публичный интерфейс для запуска
- **Methods**: Контейнер для методов-заданий

#### Основные методы
- `Start()` - Запускает главное меню
- `stop()` - Возвращает в меню после выполнения задания
- `getMethods()` - Использует рефлексию для получения всех методов класса Methods
- `menu()` - Отображает меню и обрабатывает ввод

### Использование

#### Добавление задания
1. В классе `Methods` создайте публичный метод
2. В теле метода напишите код задания
3. В конце вызовите `stop()`

```csharp
public void zadanie4()
{
    Console.WriteLine("Новое задание");
    stop(); // Обязательный вызов
}
```

#### Запуск
Раскомментируйте код в `Main`:
```csharp
StopStart stopStart = new StopStart();
stopStart.start();
```

### Преимущества
- Динамическое обнаружение заданий через рефлексию
- Не требует изменений в маршрутизации при добавлении новых заданий
- Компактная структура

### Недостатки
- Все задания в одном классе
- Ограниченная гибкость для сложных сценариев

## Ветка 2: Классовый подход с маршрутизацией (ConsoleApp1)

### Описание
Реализация, где каждое задание представлено отдельным классом, а маршрутизация выполняется через switch-case.

### Архитектура

#### Пространства имен
- **ConsoleApp1**: Основное пространство с реализацией заданий
- **jAC**: Вспомогательное пространство с интерфейсами

#### Интерфейсы
- `Tub`: Определяет метод `Run(int i)` для маршрутизации
- `Numbers`: Определяет методы `Start()` и `Stop()` для заданий

#### Ключевые компоненты
- **Lib**: Центральный управляющий класс (меню, навигация)
- **Table**: Маршрутизатор, связывает номера с классами заданий
- **Number1, Number2**: Классы, реализующие конкретные задания

### Использование

#### Добавление задания
1. Создайте новый класс, реализующий интерфейс `Numbers`
2. Реализуйте методы `Start()` и `Stop()`
3. Добавьте новый case в метод `Run` класса `Table`

```csharp
public class Number3 : Numbers
{
    public void Start()
    {
        Console.WriteLine("Задание 3");
        Stop();
    }
    public void Stop()
    {
        Lib lib = new Lib();
        lib.ToMenu();
    }
}

// В классе Table:
case 3: Number3 number3 = new Number3();
        number3.Start();
        break;
```

### Преимущества
- Четкое разделение ответственности
- Каждое задание в отдельном классе
- Легко расширяется для сложной логики
- Использование интерфейсов обеспечивает единообразие

### Недостатки
- Требует изменений в классе Table при добавлении новых заданий
- Более многословный код

## Сравнительная таблица

| Характеристика | Ветка 1 (Reflection) | Ветка 2 (Switch) |
|----------------|---------------------|------------------|
| **Обнаружение заданий** | Автоматическое (рефлексия) | Ручное (switch-case) |
| **Структура заданий** | Методы в одном классе | Отдельные классы |
| **Добавление задания** | Только новый метод | Новый класс + изменение Table |
| **Сложность кода** | Низкая | Средняя |
| **Гибкость** | Высокая | Средняя |
| **Интерфейсы** | Отсутствуют | Присутствуют |
| **Масштабируемость** | Ограниченная | Высокая |

---

## Общие характеристики

### Навигация в обеих программах
- Ввод номера задания - запуск соответствующего задания
- Ввод "stop" - завершение работы программы

### Обработка ошибок
- Проверка формата ввода (число или "stop")
- Защита от неверных номеров заданий

### Пользовательский опыт
- Очистка консоли для лучшей видимости
- Ожидание нажатия клавиши перед возвратом в меню
- Информативные сообщения об ошибках

---

## Рекомендации по выбору

### Выберите ветку 1 (Reflection), если:
- У вас много простых заданий
- Вы хотите быстро добавлять новые задания
- Вам важна компактность кода
- Задания не требуют сложной логики

### Выберите ветку 2 (Switch), если:
- Задания имеют сложную логику
- Каждое задание требует отдельной настройки
- Вы планируете добавлять зависимости в задания
- Вам важна четкая организация кода
